# Python 初学者源码导读

这份导读不是要求你从第一行读到最后一行，而是给你一条**能真正走通**的路线。

项目里有一些文件很长：

| 文件 | 大约行数 | 初学阶段 |
| --- | ---: | --- |
| `app.py` | 150 | 必读，程序入口 |
| `modscope/models.py` | 210 | 必读，数据结构 |
| `modscope/analyzer.py` | 1400+ | 只先看主流程和一条规则 |
| `modscope/metadata.py` | 1200+ | 只先看 Fabric 一种格式 |
| `modscope/versions.py` | 580 | 版本比较较难，最后看 |
| `modscope/server.py` | 450 | 了解接口即可 |
| `modscope/web/styles.css` | 1400+ | 可以完全跳过 |

> 记住：**读源码的目标是回答一个问题，而不是把每个文件背下来。**

---

## 1. 先跑起来，再读

在项目根目录执行：

```bash
python app.py
```

浏览器打开 `http://127.0.0.1:8765`，实际扫描一个小型 `mods` 文件夹。  
你会先看到“输入是什么、输出是什么”，这比直接看源码更重要。

如果想看终端输出：

```bash
python app.py scan "你的 mods 文件夹" --mc 1.20.1 --no-deep
```

`--no-deep` 会跳过类文件深度扫描，输出更短，适合第一次阅读。

## 2. 整体流程

```text
start.bat / python app.py
        │
        ▼
app.py ───────────────► 启动本地 Web 服务（server.py）
        │                        │
        └── CLI scan             └── 浏览器 POST /api/scan
                                     │
                                     ▼
                            discover_path_files()
                                     │
                                     ▼
                            Analyzer.analyze()
                                     │
                  ┌──────────────────┼──────────────────┐
                  ▼                  ▼                  ▼
             _scan_one()       _check_*() 规则      生成 findings
                  │                  │                  │
                  ▼                  ▼                  ▼
        metadata.py 读取 JAR   依赖/版本/类冲突     report 字典
                                                         │
                                                         ▼
                                              web/app.js 渲染页面
```

后端负责“读 JAR、找问题”，前端负责“把报告画出来”。

## 3. 推荐阅读顺序

### 第 1 站：`app.py`

先只读三个地方：

1. `main()`：程序从哪里开始
2. `_scan()`：命令行模式如何调用扫描器
3. `build_parser()`：参数如何进入程序

读完以后回答这个问题：

> 双击 `start.bat` 后，是哪一行代码最终启动了 Web 服务？

提示：`start.bat` → `app.py` → `main()` → `_serve()` → `run_server()`。

### 第 2 站：`modscope/models.py`

这个文件定义数据“长什么样”，几乎没有算法。

重点认识：

- `ModRecord`：一个 MOD 的 ID、版本、依赖、Mixin 配置等
- `JarRecord`：一个 JAR 文件本身的信息
- `Requirement`：一个 MOD 需要什么依赖
- `Finding`：扫描发现的一条问题
- `ScanOptions`：用户选择的 MC 版本、加载器、运行端等

看到 `@dataclass` 不要紧张，可以把它理解成：

```python
# 普通写法
mod = {
    "id": "example",
    "version": "1.0",
}

# dataclass 写法
mod = ModRecord(id="example", version="1.0")
```

类型注解 `list[str]`、`str | None` 只是“这里的值是什么类型”的提示，不影响你理解流程。

### 第 3 站：跟一条“缺少依赖”问题走

这是最适合入门的完整链路：

1. `Analyzer.analyze()`：总调度入口
2. `_scan_one()`：打开 JAR，收集 class 和元数据
3. `metadata.read_jar_metadata()`：判断这是哪种加载器格式
4. `parse_fabric_metadata()`：先把 Fabric 这一种看懂
5. `Requirement`：Fabric 的依赖被转换成统一结构
6. `_check_dependencies()`：检查依赖是否存在、版本是否满足
7. `Finding`：把问题变成报告对象
8. `web/app.js`：搜索“缺少必需依赖”，看它如何渲染

一个依赖扫描的简化逻辑：

```python
for 每个已安装 MOD 的每条依赖:
    if 依赖 ID 不在已安装列表里:
        记录“缺少依赖”
    elif 已安装版本不满足版本范围:
        记录“依赖版本不满足”
```

真实代码会多处理 `.disabled`、Jar-in-Jar、可选依赖、Quilt `unless` 等情况，但核心就是这个循环。

### 第 4 站：测试是最好的例子

`tests/test_analyzer.py` 会亲手创建假 JAR，然后验证扫描结果。  
先看 `_basic_pack()` 和 `test_missing_and_disabled_dependencies()`。

运行全部测试：

```bash
python -m unittest discover -s tests -v
```

只运行一个测试：

```bash
python -m unittest tests.test_analyzer.FabricAnalyzerTests.test_missing_and_disabled_dependencies -v
```

只运行版本比较测试：

```bash
python -m unittest tests.test_versions.VersionComparisonTests -v
```

学习方式：

1. 先读测试的输入。
2. 猜输出应该是什么。
3. 运行测试。
4. 如果结果和你想的不一样，再去看对应实现。

### 第 5 站：`versions.py`

这是全项目最“数学化”的部分，不建议第一个读。

先理解三个类：

- `Version`：版本号，负责比较大小
- `Interval`：一个区间，例如 `[1.20.1, 1.21)`
- `VersionSpec`：多个区间的并集，例如 `<=1.12 或 >=1.14`

再看三个解析函数：

- `parse_maven_range()`：Forge / NeoForge 的 Maven 范围
- `parse_fabric_predicate()`：Fabric 的谓词
- `parse_quilt_spec()`：Quilt 的版本规则

不要靠读代码硬记规则。先看 `tests/test_versions.py` 中的例子：

```python
parse_fabric_predicate("1.20.x").matches("1.20.4")  # True
parse_fabric_predicate("1.20.x").matches("1.21")    # False
parse_maven_range("[1.20.1,1.21)").matches("1.20.1") # True
```

### 第 6 站：Web 部分

- `server.py`：本地 HTTP 服务，处理 `/api/scan`
- `web/index.html`：页面结构
- `web/app.js`：发送请求、筛选结果、渲染报告
- `web/styles.css`：样式，**可以跳过**

不用先学完整的前端。只要知道：

```text
浏览器提交选项 + 文件/路径
        ↓
本地 Python 返回 report JSON
        ↓
app.js 读取 report.findings 并创建卡片
```

## 4. 需要的 Python 知识对照表

| 写法 | 在项目里代表什么 |
| --- | --- |
| `def f(x: str) -> int:` | 函数 f 接收字符串，返回整数；类型注解可先忽略 |
| `list[str]` / `dict[str, int]` | 列表里装字符串、字典的键和值类型 |
| `str | None` | 可能是字符串，也可能是空值 |
| `@dataclass` | 把一组字段自动变成初始化方法 |
| `with open(...) as f:` | 代码块结束后自动关闭文件 |
| `with zipfile.ZipFile(...)` | 把 JAR 当作 ZIP 读取 |
| `try: ... except ValueError:` | 解析失败时不要让整个程序崩溃 |
| `[x for x in items if ...]` | 列表推导式，相当于“带筛选的 for 循环” |
| `{x.id for x in items}` | 集合推导式，自动去重 |
| `defaultdict(list)` | 字典的键第一次访问时自动创建空列表 |
| `Counter(items)` | 数每个东西出现多少次 |
| `Path("...").iterdir()` | 跨平台遍历文件夹 |
| `json.loads()` / `tomllib.loads()` | 读取 JSON / TOML 元数据 |
| `raise ScanError(...)` | 主动抛出用户可读的错误 |

如果其中任何一个不熟，不需要停下来补完整本 Python 教材。先查这个写法的意思，再回到代码。

## 5. 调试：让程序停在你想看的地方

### 方法 A：命令行 + breakpoint

在某一行插入：

```python
breakpoint()
```

然后运行：

```bash
python app.py scan "你的 mods 文件夹" --mc 1.20.1 --no-deep
```

程序会进入 pdb。常用命令：

```text
p mod                 查看变量
p requirement
p providers.keys()
n                     下一行
s                     进入函数
c                     继续执行
q                     退出
```

### 方法 B：VS Code

1. 用 VS Code 打开项目根目录。
2. 安装 Python 扩展。
3. 选择 Python 解释器。
4. 在 `analyzer.py` 想观察的行号左侧点红点。
5. 在终端运行 CLI 扫描命令，或配置 `launch.json` 启动 `app.py`。

建议首次停在这些位置：

- `Analyzer.analyze()` 的 `findings = ...`
- `_check_dependencies()` 循环开头
- `_check_classes()` 遍历 class 的地方

### 方法 C：直接打印

临时加：

```python
print("mod:", mod.id, "requires:", requirement.alternatives)
```

观察完删掉即可。

## 6. 建议的两小时路线

| 时间 | 做什么 |
| --- | --- |
| 0–15 分钟 | 启动网页，扫描一次真实 mods 文件夹 |
| 15–35 分钟 | 读 `app.py` 和 `models.py` |
| 35–70 分钟 | 在测试中跟一条依赖问题 |
| 70–95 分钟 | 用断点停在 `_check_dependencies()` |
| 95–120 分钟 | 翻一遍 `app.js` 的报告渲染 |

不要一开始追求“全部理解”。能自己回答下面三个问题，就已经很棒：

1. 一个 JAR 从哪里被打开？
2. 一条 Missing Dependency 是怎么被判断出来的？
3. 最后前端从哪里拿到 `findings`？

## 7. 不建议初学阶段做的事

- ❌ 从 `styles.css` 第一行读到结尾
- ❌ 把 `metadata.py` 里所有加载器格式一次读完
- ❌ 试图记住 `versions.py` 中所有运算符分支
- ❌ 在循环里盲目加大量 `print()`，不看调用栈
- ❌ 为了看懂代码先重写整个架构

先顺着一条用户能感知的问题（比如“缺少依赖”）走一遍，你会进步最快。
